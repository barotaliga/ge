A game's items are two lists in its own data: readings (class and variant bits needed → role,
tried in order, variant first) and spawns (role → class and the variant bits it takes). A swap
is `known` false when the first game does not read the item (dropped and counted) and `becomes`
empty when the second game has no spawn for the role (dropped on purpose: a shard, a silencer).
When a pairwise mapping is not symmetric (the sequel's three energy weapons all become the classic
beam), give each its own role and let the other game spawn several roles as one class. To change
a table like this safely, compile the old header under another namespace beside the new one and
compare every class and every variant bit before deleting the old one.
