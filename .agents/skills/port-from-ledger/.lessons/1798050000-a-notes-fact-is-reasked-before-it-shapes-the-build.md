title: A gap note's summary of a behaviour is re-asked before it shapes the code

The Quake II server ledger's `feat.dl.pieces` row and its gap note said the reference sends
"several pieces a frame within the rate". A reader asked eight narrow questions (who gets it, when
it is sent, what the room is, how the rate applies, does `nextdl` still matter) found one piece
owed per `nextdl`, filling the packet, then a pause of its bytes over the rate. Building from the
note's one line would have flooded the reliable stream. When a row's note compresses a mechanism
into a phrase (a pace, an order, a limit), spend one short reader round on it before the code,
and put the answers in a facts page the row links (`q2-downloads-pace.md`).
