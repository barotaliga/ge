Status: done
Milestone: **Launching servers** (`engine/server/spawn`, `ge server`): the game's HOST page spawns its dedicated binary as its own process on macOS, Linux and Windows, hands it a cfg, joins it, finds it again by its local address after a restart and stops it; the dedicated server launches matches (the rotation, a mode, a mod switch that remounts the search path and re-reads the config layers); `ge server --game=<g> --map --bots --for` for any game with a server
Exit: A client spawns a dedicated server, joins it, quits, a second client finds it and stops it; a mod switch re-reads the layers and the next match runs under them
Labs: `server-launch`

Desktop only: the stores forbid spawning processes, so there a game hosts a listen server.
Design: [`docs/servers.md`](../servers.md) § The shape.

- Built: `engine/server/spawn` (the dedicated binary started detached with a cfg handed over as
  `+exec server-<port>.cfg`, recorded as `hosted-<port>.txt` in the game's state folder, found
  again by the record and a ping of the session's advert, stopped with its record dropped); the
  process helpers moved from `engine/gamecli` to `engine/server/process`, and the game CLI's `host`
  records are the same ones; `gesample`, the sample game's dedicated server; the `server-launch`
  lab (start with a cfg, ping, join, leave, a second program finds it from the state folder,
  switches its mods and stops it) and `tests/server_spawn_test.cpp`.
- Built: the mod switch. A dedicated server runs the console lines added to its `--commands` file
  (spawn hands it `<state>/console-<port>.txt`; `hosted_command` writes there); `mod <dirs>` resets
  every server value, remounts the search path, reads the layers again with the command line kept
  (`server_switch_mods`, `tests/server_cfg_test.cpp`) and restarts the match under them on the
  same port; a mod whose cfg refuses keeps the mods before.
- Built: a game's player CLI hosts through the launcher: `host --dedicated` is `spawn_server`
  (a cfg handed over with `--cfg=<file>`), `host send <port> <line>` reaches the server's console
  (`host send 27500 mod arena`), `host stop` drops the cfg and the console with the record.
- Built: `ge server [--game] --map --bots --for` (`engine/cli/server.hpp`): the repo's dedicated
  binary (its `ge_add_server` target alone) built and run headless offline for its digest and input
  log, `--replay=<log>` to the bit, `--port` for players; `ge server cfg [<prefix>]` the binary's
  `--explain`; `tests/cli_server_test.cpp` runs gesample twice to one digest.
- Built: Shooter's Edge's HOST page (NEW GAME) has SERVER: THIS WINDOW or DEDICATED. DEDICATED
  starts `sesv` beside the window through the launcher with the page's rules as a cfg (`-classic q2`
  for Quake II), recorded in `<prefs>/cli` (the player CLI's state folder, so `secli host list`
  sees it), and joins it; a second START joins the one running; STOP YOUR SERVER ends it
  (`games/shooters_edge/client/host_dedicated.hpp`, `tests/shooters_edge_host_dedicated_test.cpp`,
  the `se-menu` lab's host page).
- Exit met: the `server-launch` lab starts a dedicated server with a cfg, joins it, leaves it
  running, and a second program finds it from the state folder alone, switches its mods (the
  layers read again, the next match under arena's seats) and stops it; it runs in labs-smoke.
- Left for later rows: a classic map rotation's own switch (`sv_maprotation` is read where a game
  runs it) and a match mode switched by a console line beside `mod`.
