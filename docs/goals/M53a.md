Milestone: **The server core** (`engine/server`): `Server` owning the node, the session host, the hosting (M17r) and the server's console; `ServerGame`, the game's table of functions (the map's world, a player in and out, input, the step, what each client sees, the state for the input log and digest, the phase events); the frame on the run clock (`engine/loop`); a listen server stepped by the client loop with the host's player on a loopback link, and a dedicated one by the engine's `main` (`--port`, `--ip`, `--maxclients`, `--name`, `--description`, `--for`, `--realtime`, `--log`, `--replay`); `ge_add_server` in CMake; Shooter's Edge's `sesv` rebuilt on it with its digests unchanged
Exit: The same game program served by a listen and a dedicated `Server` on the simulated network gives the same digest; `sesv`'s golden and `se-server` digest unchanged after the move
Labs: `server-core`

The core every game's server stands on (design: [`docs/servers.md`](../servers.md) § The shape).
The dedicated `main` takes over what `games/shooters_edge/server/bin/main.cpp` does today (flags,
status lines, the input log and its replay, pacing), generic over `ServerGame`.

**Built (part one):**

- `engine/server`: `ServerGame` (the game's table: create, frame, its length, seated, hash,
  status, the input log and its replay), `Server` (the frame on the frame count's clock, then the
  node, the session host and the hosting at that time; offline with no socket), the settings'
  cvars (`sv_hostname`, `sv_description`, `net_ip`, `net_port`, `sv_maxclients`, `sv_map`,
  `sv_bots`, `sv_seed`, `sv_password`, `sv_visibility`), `server_main` (`server.cfg` from `--dir`,
  then the flags, then `+commands`; a cfg's mistake stops it at file:line), the status line and
  banner.
- `net/hosting`: `HostingConfig::seated`, so the LAN advert counts a game's bots and other
  protocols' players beside the session's seats.
- `cmake/Server.cmake`: `ge_add_server`. `sesv` is Shooter's Edge's `ServerGame`
  (`server/dedicated.hpp`) over the engine's main, its host run frame for frame.
- The sample game and the server trial (`server/sample.hpp`, `trial.hpp`): dedicated, listen (a
  144 Hz client loop) and networked runs of one server, a LAN browser and joining players;
  `tests/server_core_test.cpp` and the `server-core` lab.

**Built (part two):** a game that speaks its own protocol is handed the port by the core
(`ServerGame::serve`, `net_frame`: no node, session or LAN hosting of the core's on it), and
`sesv` serves the game's own deathmatch (the baseline mod) over the classic
protocol on it (`games/shooters_edge/net/classic_game.hpp`): a classic client connects and plays,
offline and networked-alone give one digest, sessions replay to the bit
(`tests/shooters_edge_classic_game_test.cpp`, the `se-dedicated` lab). The host with stand-in
bots stays a `ServerGame` for the `se-server` lab. Its map comes from the game folder under
`--root`, loose or inside a pack (a pack map held by the same test).

**Built (part three):** map changes on the dedicated server. When the mod ends a match (its time
or frag limit, then its intermission) and asks for a map, the next map's server is made from the
same settings, `sv_maprotation` picking the next map when it has one, and the classic endpoint
moves onto it (`classic_change`): every client is told the map is changing and signs on again, and
the classic client goes back through the signon to `begin` (`reconnect`). A map that does not load
leaves the server playing the one it was on, the status line saying why. Held by
`tests/shooters_edge_classic_game_test.cpp` (a client taken along to the second map, the session
replayed; a rotation from a pack's map to the arena).

**Built (part four):** Shooter's Edge's listen server on the core. A match in the window is a
`Server` on the same `classic_game()` the dedicated binary runs, opened in the window's process with
the window's program, map and lines (`client/listen.hpp`'s `ListenHost` in `ServerConfig::host`).
The player is slot 0, a local seat whose moves go into each frame and whose prints, effects and
blows the endpoint hands back (`ClassicServer::local_tap`, `local_print`); the lobby, the bots and
the restart into the match are the server's. Others join the window's match on `sv_port` like a
dedicated server's clients. A campaign stays on its own host. Held by
`tests/shooters_edge_classic_game_test.cpp` (a classic client joins the window's match over the
simulated network and sees its player) and the listen's own tests.

- 2026-11-13: short names for Shooter's Edge's programs, all at the build's root: `se` (the
  window), `sesv` (the dedicated server; `--sequel` for the sequel's rules, which had a binary of
  its own), `sefwd`, `seproxy` (`near`, `far`) and `setv` (`--sequel`), the last three one source
  (`net/hops_main.cpp`, `SE_HOP`) in place of `shooters_edge_hops <kind>`.
