Labs: `server-core`

The core every game's server stands on (design: [`docs/servers.md`](../servers.md) § The shape).
The dedicated `main` takes over what `games/shooters_edge/server/bin/main.cpp` does today (flags,
status lines, the input log and its replay, pacing), generic over `ServerGame`.

**Built (part one):**

- `engine/server`: `ServerGame` (the game's table: create, frame, its length, seated, hash,
  status, the input log and its replay), `Server` (the frame on the frame count's clock, then the
  node, the session host and the hosting at that time; offline with no socket), the settings'
  cvars (`sv_hostname`, `sv_description`, `net_ip`, `net_port`, `sv_maxclients`, `sv_map`,
  `sv_bots`, `sv_seed`, `sv_password`, `sv_visibility`), `server_main` (`server.cfg` from `--dir`,
  then the flags, then `+commands`; a cfg's mistake stops it at file:line), the status line and
  banner.
- `net/hosting`: `HostingConfig::seated`, so the LAN advert counts a game's bots and other
  protocols' players beside the session's seats.
- `cmake/Server.cmake`: `ge_add_server`. `shooters_edge_server` is Shooter's Edge's `ServerGame`
  (`server/dedicated.hpp`) over the engine's main, its host run frame for frame.
- The sample game and the server trial (`server/sample.hpp`, `trial.hpp`): dedicated, listen (a
  144 Hz client loop) and networked runs of one server, a LAN browser and joining players;
  `tests/server_core_test.cpp` and the `server-core` lab.

**Still open in M53a:** Shooter's Edge's listen server (`client/listen.cpp`) stepping the engine's
`Server`; the session's seats and the game's slots as one count (M53c joins them); the classic
protocol's endpoint on the same socket (with M18g's `--classic`).
