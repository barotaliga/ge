The mod SDK shipped: `mod/abi.hpp`, `cmake/Mods.cmake` and each game's mod header installed with
the release package, so `ge mod build` needs no engine tree; the sample built and loaded on
Linux, macOS and Windows in CI; `ge mod check --run` plays the game's mod scenario with a package
and replays it. Design: [`docs/mods.md`](../mods.md) § Rows.

## Progress

- The SDK: done. The release package installs `share/gameengine2/sdk/` (the tree's layout:
  `cmake/Mods.cmake`, `cmake/Fp.cmake`, `engine/mod/abi.hpp`, each game's `GE_MOD_SDK_FILES`),
  also alone as the `mod_sdk` component; `ge mod new` refuses an `--engine` with no
  `cmake/Mods.cmake`. The packaging workflow makes, builds and loads a mod from the installed SDK
  on Linux, macOS and Windows. Docs: [`docs/mods.md`](../mods.md) § The SDK.
- `ge mod check --run`: done. The game's own CLI plays the package in its mod scenario
  (`secli mod run <package>`, the `mod` lab's scripted match) once without it and twice with it;
  `ge` refuses the package when the two runs part (naming the frame) and reports what it changed
  and its hooks' share of the match's time. `ge` finds the CLI by `--runner`, beside itself, or
  on the PATH. The packaging workflow runs it on the SDK's mod on Linux, macOS and Windows, so
  the replay is held on each desktop OS. Tests: `tests/shooters_edge_cli_mod_run_test.cpp`,
  `tests/cli_mod_test.cpp`. Docs: [`docs/mods.md`](../mods.md) § The commands.
