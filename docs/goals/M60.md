Status: open
Milestone: **Shooter seams: shared layers and per-game modules**
Exit: Every piece more than one classic game uses lives in `plugins/shooter` or the engine, each classic game's own code sits behind one module table that remix and any later shooter game load, and nothing shared asks which game is running
Labs: `se-net`, `se-sequel-net`, `se-interop`

Asked by the maintainer on 2026-11-14: the engine holds the broad services every game shares
(accounts, the hub, proxy, forward, TV, the dedicated server, the guards); `plugins/shooter` holds
everything a shooter game shares (formats, the protocol family, the rules runner's seam, bots,
movers, remix's machinery); each classic game's own code is a thin module that remix can load into
another shooter game. A third classic game, a fourth and a game of another family (a grid-map
shooter) are kept room for and not built. The survey behind the plan, with its diagram:
https://claude.ai/artifact/NwWyMmGUsJK4HWbBxGqjtj.

The survey's findings, in the order of their pull requests:

- **M60a (this PR): the protocol family.** The net channel, the info strings and the wire's fields,
  quantization and CRC-16, which the first game's protocol and the sequel's share, move from
  `games/shooters_edge/net/classic_*` to `plugins/shooter/protocol/` (`channel.hpp`, `info.hpp`,
  `wire.hpp`); `net/protocol.hpp` names them in the game's net namespace. Each game's own protocol
  keeps its version, ports, move checksum and usercmd (`net/classic_wire.hpp`). No behaviour
  changes: the quantize golden moves with the code (`tests/golden/shooter_protocol_quantize.txt`)
  and every other golden and digest is unchanged.
- **M60b: the content layer.** The game adapter's table, the search path and the shared open
  calls (models, skins, textures, sounds, pictures) into `plugins/shooter/content/`, so any shooter
  game opens any classic game's files through one call.
- **M60c: the player CLI's groups.** The modder's commands `ge` has and the game CLI lacks (pak,
  qc, mod check and pack, cfg check and dump, the map tools, content scan) become row groups on the
  game CLI's frame (`engine/gamecli/`, `plugins/<name>/cli/`), which `ge` calls too: one body,
  two front doors. The two copies of demo pack and unpack become one.
- **M60d: the rules runner's calls.** Each place shared code asks `sequel_of(rules)` or
  `qc_of(rules)` (about 50) becomes a call on `RunnerCalls`.
- **M60e: bots off the server's types**, then `games/shooters_edge/bots` into `plugins/shooter`.
- **M60f: item roles.** Remix's pairwise item rows become one table a game, each game's items to
  shared roles (with the remix thread, M18u).
- **M60g: the game module table**, the sequel's files behind it in a library of their own, then
  the first game's.
- **M60h: the movers kit and the monster kit**, one shared state machine each with every game's
  numbers as data, goldens on both games.
