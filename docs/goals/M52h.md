No QC of our own (AGENTS.md's C++ rule): the baseline mod's sources in
`games/shooters_edge/qc/` (the arena, the campaign and `common/`, about 6,700 lines) become C++
mod packages that play exactly as the QC does, and the QC is deleted. The QC and compiled-module
machines stay, to run other people's mods unchanged.

**The design: a native program on the classic server.** The QC server is the classic game
server: its catalogue of calls (traces, finds, sounds, prints, messages, the spawn parms), its
entity memory laid out by the program form and the program's own fields, its map loading, hooks
by name and spawn functions by class name. A rules package keeps all of it and replaces only the
bytecode:

- The package DECLARES its program: the form (multiplayer or single-player), its own fields and
  their types in order (after the form's), and its functions by name (the hooks the server finds
  by name, the spawn functions by class name, and its thinks and touches unnamed).
- The server SYNTHESIZES a program from that declaration: the form's globals and fields, the
  package's fields at the offsets a compiled program would give them, and every function of the
  package as a function whose body is a call into the package. Everything that runs a program
  (load_map, the hooks, `self.think()` from another function, the free rule, the mirror between
  the loop and the entity memory) runs it unchanged.
- The package CALLS the server's catalogue through one services entry, a call by builtin number
  with typed arguments, so it reaches exactly the code the bytecode reaches (the same traces, the
  same random stream, the same message bytes). Fields and the form's globals by offset, strings
  passed as text. A typed C++ header over it reads like the QC it replaces.
- The package's own globals are its state block (copied by a snapshot, folded into the digest).

Parity, not a rewrite: each function is carried over statement for statement, in 32-bit floats
in the same order of operations (no FMA, the engine's flags), so a match plays the same. Held by
a test that runs the QC build and the package side by side and compares the loop and the entity
memory every frame; once the package holds it, the QC goes.

**Progress.**

- Step 1, the native program form: done in this pull request. `plugins/progs/native.hpp` builds a
  progs from a declaration (the form, the program's own globals, fields and strings, its functions
  by name with their parameters), each function a record numbered from `kNativeBase` that the VM
  runs as C++ (`Vm::natives`); the form's hook globals hold the functions of their names, as a
  compiler leaves them. `games/shooters_edge/rules/calls.hpp` types the classic server's
  globals, fields and calls for rules in C++ (each call the catalogue's builtin at its number), and
  the mod server runs a native program (`ModMatchOptions::native`; a progs carries its C++ in
  `Progs::natives`, which `create_vm` binds, so any server or lab that runs a progs runs one).
  The test mod in C++ (`test_mod_native.cpp`) plays the assembled test mod's match identically:
  every path, frag, print, hook call and builtin count, and the loop's digest every frame
  (`tests/shooters_edge_native_rules_test.cpp`). Left for the package step: the declaration and
  the calls behind the mod ABI (one services entry, `docs/mods.md`), so the arena ships as a
  package rather than linked in.
- Step 2, the arena: done. `games/shooters_edge/rules/arena*.cpp` carry `common/` and the arena's
  QC function for function (`arena_decl.hpp` declares its globals, fields, strings and functions
  under the QC's names; `arena_program.cpp` lays them out). Played side by side with the compiled
  QC on the baseline arena (deathmatch, deathmatch 4, a loaded game's words with teams), every
  path, frag, print, mover, hook call, builtin count (but the two text calls the QC needed to read
  a number) and the loop's digest agreed every frame; those matches are pinned now
  (`tests/shooters_edge_arena_rules_test.cpp`). `server/baseline_mod.hpp`'s `baseline_mod` and the
  client's `baseline_progs` return it, so every server, lab and test that played the QC arena
  plays the C++ one; the arena's QC (`qc/arena/`) and its built-in sources are deleted. Lab
  digests that fold a think's number or a string's place moved with the program's layout (the
  play did not: the pin holds it). `qc/common/` stays for the campaign. Next: step 3, the
  campaign, part by part, each held side by side.
- Steps 3 and 4, the campaign: done. `games/shooters_edge/rules/campaign*.cpp` carry the
  campaign's QC function for function (`campaign_decl.hpp`; the world and the level flow, the
  senses and states, the roster, the bosses, the set pieces), on the rules the two variants share
  (`common_*.cpp`, compiled once for each declaration through `variant.hpp`). Played side by side
  with the compiled QC on the coop hall (one companion; two on hard; to the exit), every frame's
  digest, kill, door, button, death and exit agreed; those runs are pinned now
  (`tests/shooters_edge_campaign_rules_test.cpp`), and every campaign behaviour test passes on
  the C++ campaign. The episode played both ways (`se-coop-episode --maps=4
  --map-seconds=240` on the shareware pack) folds to the same run digest, `f82d99eb1bd460a6`,
  with the same metrics and the same picture. `server/baseline_mod.hpp`'s `campaign_mod` returns it (`own_mod` by name for
  a lab's `--progs=campaign`), so the co-op runs, the episode and every lab play it. The last QC
  of our own (`qc/campaign/`, `qc/common/`, the README) is deleted; `ge qc build` stays for
  other people's QC. Next: the package step (the declaration and the calls behind the mod ABI,
  `docs/mods.md`), then M52g.
