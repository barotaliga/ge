## Progress

- 2026-11-12: the engine's proxy pair (`engine/proxy/proxy.hpp`): a near proxy beside the client and a far one near the server, sessions opened by a padded request and a cookie with an allow list on the far side; each datagram repeated up to five times with a gap and passed on once, and packed (XOR against the newest datagram the other end confirmed, zero runs counted). The trial (`trial.hpp`) and the `proxy` lab: at 10% loss on the link the game loses 10.3% plain and 0.12% with three copies; packing sends 30% of the plain bytes down. `tests/proxy_test.cpp` holds both exit numbers.
- 2026-11-12: recording on the proxy (`engine/proxy/record.hpp`): every game datagram either proxy passes on (`ProxyConfig::tap`) kept as a replay file, two message tracks, read back in order; observers through a TV node fed the file as it grows (`proxy_record_fresh`); `tests/proxy_test.cpp`.
- 2026-11-13: a classic client through the proxy pair to a real server (`se-interop --proxy=<port>`, an open-source classic server and match mod built beside the checkout): at 10% loss each way on the link the client counts 20.9% of the server's packets lost with one copy and 1.3% with three (1.1% on a clean link), sixteen times fewer. That took a fix: copies that have fallen due now go before a newer datagram (`tests/proxy_test.cpp` `due_copies_go_before_a_newer_datagram`), since a copy behind a newer datagram arrived too late for a game that drops older packets. Packing does not shrink the classic game's short delta datagrams: the link costs about a third more than the game's bytes with one copy.
- Next: the field codec on the link for a game with a schema (the classic link's bytes), and a smaller frame header.
