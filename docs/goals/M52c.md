Mods where native code may not load: the portable form (the same source compiled to a
WebAssembly module, a `wasm32` row in the manifest), the engine's own interpreter for it (no JIT,
every import one of the ABI's tables, bounded memory and fuel), the iOS and Android builds
loading only that form, and ahead-of-time linking for a mod a store build ships inside the app.
Design: [`docs/mods.md`](../mods.md) § Platforms.

## Progress

- The interpreter: done. `engine/mod/wasm/` reads a module (the MVP binary format and what clang
  emits by default), validates and compiles every body to resolved instructions, and runs them
  with fuel, a bounded stack and call depth, bounded memory, named traps and the canonical NaN.
  Host functions come in as imports and through the table. Tests: `tests/mod_wasm_test.cpp` (a C
  module compiled by clang, kept as its bytes in `tests/mod_wasm_fixture.hpp`; traps; NaN bits;
  copies; refusals; every byte changed). Docs: [`docs/mods.md`](../mods.md) § The store form.
- The mod ABI over the interpreter: done. `engine/mod/wasm/mod.hpp` loads a mod's module (its
  entry, its table and hook table in wasm32's layout) and lays the host table, the game's services
  and the state block out in its memory; `bind.hpp` binds native functions by their C++ types.
  Shooter's Edge hosts a module behind its native seam (`create_wasm_mod_host`), and
  `rocket-bounce` built for wasm32 (`ge_add_mod(... WASM)`, where clang and wasm-ld are found)
  plays the scripted match to the native library's hashes on every frame and survives a seek.
  Tests: `tests/mod_wasm_mod_test.cpp` (a clang-built test mod kept as bytes),
  `tests/shooters_edge_mod_test.cpp`. The `mod` lab's store-form section shows the two builds'
  frames, hashes and rockets side by side (measured, so a build without the toolchain keeps the
  digest).
  Next: `ge mod build --wasm` and the manifest's `file.wasm32` row, the loader reading it, and the
  store builds (iOS, Android) loading only that row.
