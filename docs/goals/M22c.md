Status: in progress

Built: `games/fall_line/app/menus.hpp`, Fall Line's shell. The app opens on the FRONT DOOR over
the live mountain: the bot skis the map behind the title, seen from the chase camera, and starts
again from the top once he is down. The picture is softened by a scrim on the column's side and a
vignette. PLAY starts the run. On the run, Escape stops it under the PAUSE page, where the picture
is dimmed; RESUME or Escape returns to the run, and QUIT TO TITLE goes back to the front door.
OPTIONS sets the camera's view, the sound and the master volume, starting from their cvars
(`cl_view`, `s_mute`, `volume`); both menus share one `MenuSettings`, which the app reads every
frame. Every word comes from `kMenuText`. The player's runs are the by-hand runs of M19c: PLAY
opens a fresh one on the same map, the bot pilots the runs behind the front door, and the input
log written at the end is the player's latest run (none when no run was played). `--play`,
`--bot` or a scripted session (`--events`) starts on the run with no front door, so a session
steps the same run it did before.

The menus make three sounds: `menu_focus`, `menu_press` and `menu_page`
(`games/fall_line/sound/bank.hpp`, played by `play_menu`). The frame has a `ui` row after post
(`games/fall_line/app/frame.hpp`), which draws the overlay `draw` is handed with the 2D pass
(`render/ui_pass.hpp`). Without an overlay it draws an empty pass. With it Fall Line's frame has
33 passes, so the pass table's cap (`kMaxPasses`, render/frame.hpp) is now 48.

The `front-door` lab draws the three pages over the frame at 1280x720, 390x844 and 844x390 and
holds every page of both menus to `layout_problems`, which must be empty. The tests in
`tests/fall_line_menus_test.cpp` walk the shell's modes, the options and the sound cues.
