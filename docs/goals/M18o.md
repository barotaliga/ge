The classic game loop, built in a clean room: a research session wrote the behaviour in our
words (`porting/shooters-edge/movement.md`, `porting/shooters-edge/gameloop.md`) with measured
test vectors (`porting/shooters-edge/vectors/`), and a separate building session that never
read existing source builds from those notes alone (`docs/shooters-edge.md` § Licensing and
the clean room). The loop is the **classic-enhance baseline**: what Shooter's Edge does with
the classic content before any improvement, held by the parity labs, so every later change is
a measured difference from it.

- **M18o1, the move and the hulls** (`plugins/shooter`): **done.** Clip hulls and the line trace
  (`hull.hpp`), the box hull, hulls built from convex brushes (`brush_hull.hpp`), the move's
  solids and traces (`world.hpp`), the player move with every move type and server setting
  (`pmove.hpp`, `slide.hpp`), the 50 ms command split. Held by
  `tests/shooter_recording_test.cpp`: all 4033 recorded lines of the 35 scenarios within the
  tolerance, and every one equal to the recording in all nine printed digits; the move's own
  bits by `tests/shooter_pmove_test.cpp`. The `pmove` lab draws and tables it. One lab, not
  two: `se-parity` (`docs/shooters-edge.md`) runs a live existing server beside ours, which
  this row does not do, so it stays with the protocol rows; `pmove` compares against the
  committed recordings. Resolved by the recordings where the note was open: the view's radians
  are rounded to float before their sine (a player facing -x drifts sideways by the sine of pi
  in float); the recordings start with the water type 0, which a spectator keeps; the
  scenario `ramp_down_slidefix` was recorded on the 30 degree ramp but printed under the 10
  degree one (fixed at the source).
- **M18o2, the frame, the entities and the client** (`plugins/shooter`, `games/shooters_edge/sim`):
  **done.** The game-program seam (`program.hpp`: every hook, think, touch and blocked function a
  function number, so a native C++ program now and M18p's bytecode later plug into the same
  `call`), the entity pool and its fields (`entity.hpp`, `server.hpp`), the area tree
  (`area.hpp`), world traces (`trace.hpp`), the physics frame on the run clock at `sv_mintic`
  with the thinking window, toss, bounce, fly, flymissile, step, noclip and new missiles
  (`physics.hpp`), pushers (`push.hpp`), trigger and impact touches, the server's frame with
  its packets in a recorded order (`frame.hpp`), a player's packet and command with the lost
  commands, the speed check, the 50 ms chop and the landing guard (`client.hpp`), the client's
  commands (`usercmd.hpp`) and its prediction from the protocol's quantized state with error
  smoothing and other players run forward (`predict.hpp`). Shooter's Edge's native program plays
  a scripted match on a hand-built arena (`games/shooters_edge/sim`). Held by: all 454 recorded
  frames of the five thrown-entity flights within tolerance and every one exact
  (`tests/shooter_toss_recording_test.cpp`); the spec's thinking examples, pushers, touches, the
  packet and command rules, the client's commands and prediction by their own tests
  (`tests/shooter_*_test.cpp`); the physics' own bits by `tests/golden/shooter_physics.txt`; the
  match replaying to the bit with its hashes in `tests/golden/shooters_edge_match.txt`. The
  `se-loop` lab tables and draws the match and the vectors. `se-parity` (an existing server run
  beside ours) moves to M18e with the protocol rows. Resolved where the spec was open: the water
  check of a thrown entity runs only after a hit (its numbered steps stop at a full move first);
  a command's length is the running total's whole part, so 77 a second gives one 12 ms command
  and then 13s (the spec's example sequence is illustrative); the first physics frame of a map
  runs `sv_maxtic`, as the spec states, and every later one `sv_mintic` on the run clock.
