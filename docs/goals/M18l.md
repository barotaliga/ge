Status: in progress
Milestone: **Modern features**: voice on the native protocol (M17h), skeletal models beside MDL, data-driven particles, replacement textures, the common QC extensions
Exit: Each feature pictured or measured on a free map
Labs: each feature's: `gpu-particle-effects`, `se-timedemo`

**Replacement textures**: built (`client/game_adapter.hpp`'s `map_textures`: a PNG or TGA in the
game's files stands in for a map's texture by its name).

**Data-driven particles**: built. An effect is a few lines of text (`engine/particles/effect.hpp`:
bursts and trails, their shape, speeds, life, size, fall, colour or palette run, shine or smoke,
cooling, growth, streaks, bounce, a light), read whole or refused with its file, line and fix;
Shooter's Edge reads `particles/*.fx` from the game's files and throws an effect named for a
classic one in its place (`client/world_fx.hpp`). Held by `tests/particles_effect_test.cpp`,
the `gpu-particle-effects` lab (a sample book on the yard, the faults' table) and the
`se-timedemo` lab's `--particles=sample`.

**Skeletal models**: read. `engine/assets/iqm.hpp` reads a mod's `.iqm` (version 2: joints,
meshes, blend weights, animations) into the engine's `Model`, so it poses and skins as an
authored model does, and writes one back. Held by `tests/assets_iqm_test.cpp` (a round trip, the
frame, the winding, a file without joints, the faults) and the `models` lab's `--format=iqm`;
checked by hand on a real exported file (75 joints, one clip) through `--model`. **Drawn in the
game**: a model the server names as `.iqm` (or a file starting with the skeletal magic under any
name) is posed through each clip at 20 a second into a morph model's frames, a clip a frame group
(`plugins/morph/skeletal.hpp`), its materials' pictures one skin, and drawn by the window's model
pass as a classic model is (floor light, both looks, frame blending, warps, glows). Held by
`tests/morph_skeletal_test.cpp`, `tests/shooters_edge_game_adapter_test.cpp` and the `se-models`
lab's `--models=iqm`.

**A mod's own effects**: drawn on the listen server. `DP_SV_POINTPARTICLES`
(`server/catalogue.hpp`): `particleeffectnum` (#335) gives a name its number, `pointparticles`
(#337) and `trailparticles` (#336) send the effect by its name to those who see it
(`server/messages.hpp`'s `point_effect` and `trail_effect` events). The window draws an effect of
a classic name (`gunshot`, `te_explosion`, ...) as the classic effect, any other as the game's
files' effect of that name (`particles/*.fx`), or nothing when they define none; a classic client
gets the temporary entity of a classic name and nothing for any other (never a message it does
not know). Held by `tests/shooters_edge_qc_messages_test.cpp`, `tests/shooters_edge_listen_test.cpp`
and the `se-weapon-fx` lab's `--mod-effects=1`.

**Over the wire**: a remote client of the game's own gets them too. The game's own extension set
(`net/classic_ext.hpp`'s `ge` family, `named-effects`) travels as the z set does: the client puts
`*ge_ext` in its user info, the server in its server info, and only a connection where both did
is sent svc 120 (a point: name, origin, way, count) and 121 (a trail: name, from, to). A classic
client never asks, so never sees either; the client's recording files strip them, as they strip
voice, so a demo stays one any classic player reads. Held by `tests/shooters_edge_remote_test.cpp`,
`tests/shooters_edge_classic_record_test.cpp` and the wire's golden rows
(`tests/golden/shooters_edge_classic_messages.txt`).

**Voice in the window (done):** joined to a server (`connect`), the window asks for the protocol's
voice bit (`cl_voip 1`, the default) and plays the voices the server routes to the player as a
demo's voices play (`client/demo_voice.hpp`), never his own. Holding `+voip` (V by default; PUSH TO
TALK on the controls page) opens the microphone the first time (`platform/audio.hpp`'s
`open_audio_in`, so the system asks the player's leave then) and sends it as 20 ms Opus frames
with the moves. The live recording the window reads keeps the voices (`ClientRecorder::live`,
which also keeps the named effects); a recording file is unchanged. The same change plays the
joined game's sounds, printed lines and centre messages, which the window read but never played.
Held by `tests/shooters_edge_remote_test.cpp` (a scripted talker heard, the window's microphone
heard by him only while `+voip` is held, the window's own voice never played back).

**Voice on the window's own match (done):** the window's match relays voice (`sv_voip 1` while
`cl_voip` is on). Its own player is a local seat no packet reaches, so the endpoint hands him what
he hears (`ClassicServer::local_voice`, played by `client/listen_sound.hpp`) and relays his
microphone as a client's (`listen_mic` → `classic_local_voice`) while `+voip` is held; the
frames are cut by `client/voice_out.hpp`, which our client's own speaking now shares. By team, a
free-for-all (nobody on a team) is heard by everyone; before, nobody heard anybody. Held by
`tests/shooters_edge_classic_game_test.cpp` (a visitor heard by the host and the host by him only
while talking).

**The common QC extensions, a first round (done):** `DP_QC_ETOS` (`etos`), `DP_QC_FINDFLOAT`
(`findfloat`), `DP_QC_VECTORVECTORS` (`vectorvectors`), `DP_QC_ASINACOSATANATAN2TAN` (through the
vendored libm, so the bits hold everywhere), `DP_QC_STRING_CASE_FUNCTIONS` and `DP_QC_STRREPLACE`,
each answered by `checkextension` (`server/catalogue.hpp`; the VM-only ones in
`plugins/progs/stdlib.hpp`). Held by `tests/progs_stdlib_test.cpp` and
`tests/shooters_edge_qc_builtins_test.cpp`.

**The second round (done):** `DP_QC_FINDCHAIN` and `DP_QC_FINDCHAINFLOAT` (the matches linked
through `chain`, the last first) and `DP_QC_COPYENTITY` (every field, the copy linked where it now
stands). Held by `tests/shooters_edge_qc_builtins_test.cpp`.

Next in this row: the FTE string set and `DP_QC_SPRINTF`, then the entity look fields (alpha,
scale, colour) a QC mod sets.
