Status: done

The QC VM, built in a clean room from the written specification of the bytecode
(`porting/shooters-edge/progs.md`) and the public format facts (`formats.md`): a building session
that never read an existing compiler, VM or server.

- **The plugin** (`plugins/progs`, `ge::progs`, engine-side only: links `ge_core`):
  - `file.hpp`: the loader and checker. Version 6 and the crc 54730 layout; every section's
    bounds; every statement's operands, by the opcode's shape, inside the globals, and every
    jump inside the statements; every function's range, parameters and locals; every definition
    inside the globals or the entity; and the engine-side globals and fields at their offsets
    (`layout.hpp`). A refusal names the record and says what to do next. Lookups by name, the
    first match winning, and an optional line table.
  - `vm.hpp`: the interpreter. All 66 opcodes on 32-bit floats; entity and global memory; the
    32-deep call stack with the 2048-word local stack; strings (the file's, the engine's handles
    and the ring of eight temporaries); the builtin table the game fills; the world guard on
    ADDRESS; STATE; and the runaway guard (the 100000th statement of an engine call faults).
    - Every operand, entity, field and pointer is checked. A fault unwinds to the engine with
      the QC stack (function, file, statement, line). The VM refuses calls until the game clears
      the fault.
    - A per-function profile (statements, calls) and per-builtin counts.
    - Trace hooks behind a template switch, so the plain loop pays nothing for them.
    - No allocation after `create_vm`.
  - `extensions.hpp`: the extension registry. Named groups of builtins, fields and hooks; a
    duplicate name or builtin number is refused; `install` puts them in the table.
  - `assembler.hpp`: bytecode built in memory for tests and labs, with labels, calls and a line
    table.
  - `disasm.hpp`: the listing.
  - `sample.hpp`: the test program (fib, vectors, entities, strings, bits, think, a fault) with
    five builtins (`sin` through `core/libm`).
  - `tool.hpp`: the `qc` executable (`bin/qc.cpp`), which `ge qc disasm/run/trace/profile`
    builds and hands off to, because the engine's command line never links a plugin. Plugins
    may now have a `bin/` of tools (`cmake/Plugins.cmake`).
- **The adapter** (`games/shooters_edge/sim/qc_program.hpp`): a loaded progs drives the loop's
  program seam.
  - It mirrors the loop's entity fields and globals into the VM around each call.
  - It takes the hooks from the hook globals (StartFrame … SetChangeParms) and the spectator
    hooks by name.
  - It gives the seam `spawn`, `remove` and `setorigin`, at numbers the game chooses.
  - A removed entity gets the progs' free rule in the VM: the listed fields are cleared,
    nextthink is −1, and its other fields are kept.
- **Held by** 38 tests:
  - `tests/progs_ops_test.cpp`: every opcode, with its edge cases, by assembled bytecode. Golden:
    `tests/golden/progs_ops.txt`.
  - `tests/progs_vm_test.cpp`: calls, depth, the runaway guard, strings, the world guard, faults
    and their stacks, the profile, and a run replaying to the bit. Golden:
    `tests/golden/progs_vm.txt`.
  - `tests/progs_file_test.cpp`: every refusal.
  - `tests/progs_tool_test.cpp`: the tool.
  - `tests/cli_qc_test.cpp`: `ge qc`.
  - `tests/shooters_edge_qc_program_test.cpp`: assembled bytecode running a think chain under
    the physics frames, a trigger touch that hurts, spawns and sets an origin, the hooks, and a
    fault in a think.
- **The `qc` lab** (`plugins/progs/labs/qc_lab.cpp`, in `make labs-smoke`):
  - The sample's profile at five sizes, as a heatmap of where the statements go.
  - A fault's QC stack.
  - Opcode throughput by group (float, vector, compare, field, call, string, branch), as a box
    chart.
  - It attaches the sample progs and its line table for `ge qc`.

**Choices where the spec was open:**
- The runaway guard faults on the 100000th statement.
- Call depth counts the engine's entry function.
- An engine call straight to a builtin passes its declared parameter count.
- A string value is 0, a file offset, a negative engine handle, or −(0x100000 + slot) for a
  temporary. Any other value faults.
- Entity values are checked against the entities the game says are in use.
- The line table is our own sidecar (`<progs>.lines`), because the file format has none.
- Definitions with a type past 7 are refused.
- A function's locals must cover its parameters.
- The layout check reads each layout name's first definition.
