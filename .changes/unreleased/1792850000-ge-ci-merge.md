title: ge ci --merge, and why a green pull request is blocked
---

`ge ci <pr> --merge` squash-merges a pull request once every check on its head has passed and GitHub calls it clean, pinned to the head those checks ran on so a later push is never merged unseen. When GitHub blocks a pull request whose checks are all green, `ge ci` now says why: it reads the base branch's rules and names each required check that never passed on the head (a check no workflow runs is a ruleset to fix) and any required review.
