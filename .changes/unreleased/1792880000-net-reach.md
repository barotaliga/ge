type: Added
title: Reaching a host behind a home router: simulated NATs, STUN, a rendezvous, hole punching and a relay
---

The simulated network now puts nodes behind NATs of every kind a home router has (full cone, restricted, port-restricted, symmetric), with mappings that expire and port forwards. `net/stun.hpp` writes and reads STUN's Binding request and answer, so a node can learn its public address from any STUN server. `net/rendezvous.hpp` is a small public server: hosts register their sessions, a joining client is introduced to its host with a nonce, STUN is answered on the same port, and a relay port forwards between a pair that cannot reach each other. It never answers bigger than it was asked. `net/reach.hpp` drives both ends on the node's own socket: the host punches through its NAT toward the client, the client connects straight to the host and follows the port a symmetric NAT gives the pair, and falls back on the relay when no hole opens. A node can keep other protocols' datagrams for the caller (`keep_foreign`) and move a connect still in progress to another address (`node_retarget`). The new `net-reach` lab runs every pair of NAT kinds under each network preset and checks each takes the path its NATs predict.
