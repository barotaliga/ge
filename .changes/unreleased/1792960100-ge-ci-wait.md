---
type: Added
title: ge ci --wait blocks until a pull request settles
---

`ge ci <pr> --wait[=<minutes>]` checks the pull request once a minute and answers as `ge ci` does. It returns as soon as a check fails, the pull request conflicts with its base, or every check has finished, and it gives up after 60 minutes unless another limit is set. With `--merge`, a green, clean answer is then squash-merged at its head. On a base that merges only through a merge queue, `ge ci <pr> --merge` arms squash auto-merge instead, so the pull request joins the queue, and it says so. Run it in the background, and it replaces a series of scheduled check-ins. A flag's value can now be optional (`--wait` or `--wait=30`), and help shows such a flag as `--wait[=<minutes>]`.
