The store's controller layer (Steam Input's shape). `services/controllers.hpp`: `ControllerLayer` takes the game's action map once (contexts become action sets, with layers), reads each controller the store holds as action values, says which controls an action is on with a glyph name and the label the pad's family prints, rumbles, and opens the store's configurator. `merge_store_values` folds a store-read pad into the game's own values by the actions' rules, so the keyboard and the pad steer together. `action_manifest_text` and `default_config_text` write the store's in-game actions file and default configuration from the map. `SimControllers` is the layer in memory, reading virtual pads through each controller's configuration with `input::evaluate`, with the player's rebinds and a journal. The `store-input` lab holds the store-read pad to the same pad read directly (gap 0), charts the steer by source and tables every action's prompt on each family.
