title: The tree builds and tests with Apple Clang on macOS again
---

A debug build on a Mac no longer stops on the rules' deliberate both-sides `and` and `or` (Clang's bitwise-on-booleans warning is off for those sources only), a lambda's capture that shadowed its loop's name, or a count a test kept and never printed. Under AddressSanitizer on macOS a mod's library is left mapped when it is closed, since the sanitizer keeps an unloaded library's globals poisoned and the next library mapped at that address read as overflowing.
